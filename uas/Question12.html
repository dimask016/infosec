Question 12 – Risk Assessment

Complete the table below by assessing the Likelihood, Impact, and Risk Level for each API risk based on the PT GlobalRetail scenario.
Scenario Recap: IDOR vulnerability (change ID 1001→1002 gets other's data) | No rate limiting | 90-day tokens | Public API docs | Verbose DB errors | HTTPS enabled.

Penilaian Risiko API

# API Risk Likelihood Impact Risk Level Detail
1 Unauthorized Data Access High High CRITICAL

Mengapa Likelihood = High & Impact = High?

🔍 Analisis Likelihood
Kerentanan BOLA/IDOR sangat mudah dieksploitasi. Attacker hanya perlu mengubah angka customer_id (1001 → 1002) tanpa perlu teknik khusus. ID numerik bersifat prediktif, sehingga enumerasi sangat sederhana.
💥 Analisis Impact
Data yang diekspos adalah PII (Personally Identifiable Information) seperti profil, poin reward, dan histori pesanan. Kebocoran data ini dapat mengakibatkan denda regulasi (UU PDP/GDPR) dan kerusakan reputasi besar.
Referensi skenario: "The API returns another customer's personal information without verifying whether the user is authorized to access that record."
2 Account Enumeration Medium Medium MEDIUM

Mengapa Likelihood = Medium & Impact = Medium?

🔍 Analisis Likelihood
Meskipun skenario tidak menyebutkan perbedaan respons antara ID valid dan tidak valid, dokumentasi API yang publik dan error message yang verbose bisa membantu attacker menyusun daftar akun. Namun, tetap membutuhkan usaha enumerasi yang tidak selalu berhasil jika respons digenerik.
💥 Analisis Impact
Enumeration itu sendiri tidak langsung membocorkan data sensitif, tetapi dapat digunakan untuk targeted phishing atau social engineering. Dampaknya bersifat tidak langsung, sehingga dinilai Medium.
Referensi skenario: "API documentation is publicly accessible" dan "Error messages reveal detailed database information."
3 Automated Data Harvesting High High CRITICAL

Mengapa Likelihood = High & Impact = High?

🔍 Analisis Likelihood
Kombinasi IDOR (memungkinkan akses tidak sah) dan tidak ada rate limiting (memungkinkan skala besar) menciptakan peluang sempurna untuk otomatisasi. Attacker bisa menulis skrip sederhana untuk meminta ribuan ID dalam hitungan menit.
💥 Analisis Impact
Dampaknya sangat besar karena dapat menyebabkan eksfiltrasi data massal (jutaan pelanggan) dalam waktu singkat. Ini adalah skenario terburuk bagi perusahaan dan langsung memicu pelanggaran regulasi.
Referensi skenario: "Rate limiting is not enabled" dan management khawatir "attackers could exploit the API to access large amounts of customer data."
4 Token Theft Misuse Medium High HIGH

Mengapa Likelihood = Medium & Impact = High?

🔍 Analisis Likelihood
Token bisa dicuri melalui berbagai vektor (MITM, XSS, cache, logging). Meskipun HTTPS sudah diaktifkan, token tetap rentan bocor di sisi client atau server. Namun, karena membutuhkan akses ke token terlebih dahulu, kemungkinannya tidak setinggi IDOR yang langsung bisa dieksploitasi tanpa syarat.
💥 Analisis Impact
Token berlaku 90 hari. Jika dicuri, attacker memiliki waktu sangat panjang untuk mengakses semua data dan fitur yang dimiliki pengguna yang sah. Ini setara dengan pengambilalihan akun penuh (account takeover) yang dampaknya sangat tinggi.
Referensi skenario: "Authentication tokens remain valid for 90 days."
